## 最该知道的三条

### 1. 目录里有 FIFO / 设备文件时，备份会**永久卡死**

Linux 上只要源目录里有一个命名管道（FIFO）或字符设备，备份进程就会阻塞在
`open()` 上，**永远不返回**，只能强杀。

> **影响**：Linux 用户；`/var/log`、容器卷、开发目录里都很常见。

### 2. 恢复时遇到「文件 ↔ 目录」重名，会**删掉你的文件**

包里是目录、目标处同名的是你的文件（或反过来）时，旧实现直接 `unlink()` /
`rmtree()` 把用户的删掉，然后返回「已解压」。**原生 7z 在同样情况下是拒绝覆盖、
你的文件一动不动。**

> **影响**：往已有备份目录补解压、灾难恢复场景。

### 3. 源文件被其它程序占用时，产出的是**坏包**却报「成功 + 校验通过」

`tarfile` 的错误顺序导致：文件被 Excel/PSD/IDE 独占时，tar 流会**从此错位**。
实测（5 个文件锁住第 3 个）：产物只剩 3 条，`file3` 里装的是 `file4` 的名字 + 垃圾，
`file4`/`file5` **完全消失** —— 而界面打勾说「校验通过」。

> **影响**：所有人。8 位测试用户独立撞到这一条。
>
> 用户原话：「这个『校验通过』比不备份更危险 —— 它给了我一个假的安心。」

## 数据安全（会真的丢数据的问题）

- **文件被占用 → 不再产出错位坏包**：写 tar 头之前先探测可读性；被占用的文件
  跳过并登记，其余文件照常备份，任务标为 `partial` 并列出未备份清单。
  7z / zip / py7zr / tar 四个后端全部覆盖（此前只有 2 个）。
- **并发建任务不再丢失**：旧实现锁竞争超过 30 秒后会「静默降级」成不持锁继续写，
  导致 20 并发丢 90%。实测 940 次 add：超时降级=0 的 16 轮零丢失，降级>0 的 4 轮
  **全部丢失**；80 并发 400 次新增丢 83 个。现在超时会明确抛错，
  CLI 返回非 0 并提示重试。
- **配置不再整库丢失**：一次瞬态读失败（Windows 上 `os.replace` 与 `open` 的共享
  冲突）会让旧实现把 `tasks.json` 整份改名后只写当前任务 —— 10 个任务只剩 1 个。
  现在保全后立即回读合并。
- **配置合并不再被「指纹撞车」骗过**：判断「磁盘有没有被外部改动」用的是
  `(mtime, size)` 指纹，实测 300 次相邻写入中有 10 次（**2.6%**）指纹完全相同；
  加上「读内容」与「取指纹」本身不原子，会导致持锁也跳过合并 → 整库覆写。
  现在锁内**无条件重读**，不再依赖指纹。
- **跨任务不再误删别人的备份**：`backup` 任务此前会把 `backup_photos_2026…`
  认成自己的，按自己的配额删掉它的**唯一一份**。升级用户的历史清单没有 `task_id`
  字段，只能靠名字判定，因此触发窗口很大。
- **瞬态读失败不再导致整库消失**（同第 3 条）。
- **强杀后的残包不再永久堆积**：tar 后端改为写 `.bs-tmp-<pid>` 事务名，
  成功后才原子改名。此前残包文件名完全正常，清扫逻辑识别不到、保留策略也不回收。

## 校验与恢复

- **裸 tar 截断不再假通过**：`tarfile` 读到全零块就认为归档结束，所以
  「截断在 512 边界且落点是零填充」会被误判为正常结束 —— 实测 4 个截断位置
  都返回 `passed`，而尾部文件已丢。现在要求末尾存在完整的两个零块且长度对齐。
- **6 种病因不再给同一句报错**：错密码 / 没密码 / 包截断 / 缺分卷 / 文件不存在 /
  格式不支持，此前输出**除文件名外字节级完全相同**，还附一条结构上走不通的建议
  （设了也没有任何代码会去读它）。现在按 7-Zip 的 stderr 区分病因并给出真实排查方向。
- **绝对符号链接不再废掉整包**：Linux/WSL 上 `ln -s $PWD/xxx` 极常见，
  旧实现遇到它直接拒绝解压**整包**，一个文件都出不来。现在只跳过那一条链接并记日志，
  其余文件照常解出；越界的普通文件成员（真攻击）仍然拒绝整包。
- **Windows 保留名不再静默丢数据**：`CON`/`NUL`/`AUX`/`COM1` 等是设备名，
  `open()` 会「成功」但数据被吞掉，`exists()` 为 True 而 `size=0`。
  现在解压前改名为 `*_renamed` 并记日志（只在 Windows 上生效）。
- **恢复时不再删用户文件**：类型冲突改为把用户的原有项改名成 `*.conflict-N` 保留。

## 符号链接与权限

- **符号链接与硬链接不再被丢弃**：tarfile 解包此前 `continue` 掉了所有链接，
  7z/zip/rar 产物里的链接全部消失而任务报 success。现在完整保留（并校验落点不越界）。
- **权限位不再塌陷成 0644**：0600 私钥此前会变成全局可读。现在还原 mode 与 mtime。
- **`skipped_busy` 类属性共享 bug 已修**：它会让一次**完全干净**的备份继承上一次的
  「跳过清单」而误标 `partial`，进而被保留策略当垃圾回收 —— **数据丢失**。
  GUI/daemon 这类常驻进程尤其严重。

## 其它

- **`--exclude 'node_modules'` 官方示例现在真的生效**：此前目录被排除后，
  其**子文件**仍被完整打包（用户照抄文档，以为排除了，实际包塞满 `node_modules`）。
- **`re:` 正则排除不再被破坏**：旧实现把正则里的 `\.` 替换成 `/.`，导致永不匹配。
- **`source_bytes` 不再虚高 2~7 倍**：旧算法让每个文件向每一级祖先各累加一次
  （倍数 = 目录层数 + 2）。它同时污染空间预检（4 层结构实际要求 12.3 倍）与进度条
  （最多走到 22% 就跳「完成」）。
- **陈旧暂存目录会被自动清扫**：不再依赖进程正常退出时的 `finally`。
  只清理「属主进程已死且超过 60 秒」的目录，活进程的目录不动。
- **清扫不再被只读文件卡住**：`force_rmtree` 会先清只读属性再删；
  删不净时会记 warning（此前是静默失败，明文永久留在备份目录）。
